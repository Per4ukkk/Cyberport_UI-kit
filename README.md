# CyberPort UI-kit — документация

Локальный справочник в новом дизайне: 20 статей из `Описание UI-kit/`, страница типографики с 32 стилями, шесть категорий, поиск по полному тексту, оглавления и примеры из PDF. Для 15 компонентов добавлены живые примеры из существующей библиотеки `ui-kit`.

## Дизайн-ревью, код и подключение нейросети

- `/design-review/` и `/design-review/handoff/` — два утверждённых чек-листа из папки `Design review`. Канонические копии PDF и дословные транскрипции находятся в `content/design-review/`; их SHA-256 зафиксированы в `sources.json`. Первый PDF содержит текст в контурах, поэтому он перенесён по визуальному рендеру. Менять формулировки без разрешения пользователя нельзя.
- У 15 компонентов есть вкладка «Код»: пример с текущими настройками, параметры API, методы и оригинальный исходник. Общие рецепты в `public/component-docs.js` используются и живым примером, и генерируемым фрагментом. Код библиотеки в `ui-kit/` не дублируется и не изменяется при публикации документации.
- `/getting-started/` объясняет подключение. `/downloads/cyberport-ui-kit.zip` собирается из реальной библиотеки, шрифтов и оригинальных иконок. В архиве адаптируются только пути к ресурсам; JavaScript компонентов совпадает с исходниками. Сохранить `ui-kit/`, `fonts/` и `icons/` рядом, модульный HTML открывать по HTTP.
- `/ai/` содержит три копируемых промпта: ревью, handoff и разработка. Промпты содержат постоянный адрес из `content/site.json`: https://cyberport-ui-kit.vercel.app, в том числе при локальном просмотре.
- `/llms.txt`, `/ai/manifest.json`, `/ai/context.md`, `/ai/components/{slug}.md` и `/ai/sources/{file}.txt` доступны без выполнения JavaScript. `llms-full.txt` совпадает с единым контекстом правил. Манифест содержит версию по содержимому, контрольные суммы, API, пути к исходникам и ресурсам. Исходные описания доступны отдельно в `/docs/{slug}/index.md`; технические дополнения API не подменяют их.

Генерация новых разделов — `scripts/documentation.mjs`; интерфейс — `public/documentation.js/.css`. `npm run check` проверяет блокировку двух чек-листов, их HTML/Markdown/PDF, доступность файлов манифеста, SHA-256, публичный адрес промптов и соответствие кодовых примеров общим рецептам. Оригинальные 20 описаний также защищены; единственное согласованное уточнение от 30.10.2026 — подпись «Правильно» под последней иллюстрацией на странице поля ввода. Оно отдельно записано в `approvedCorrections` записи `input` в `pdf-text-lock.json`, оригинальный PDF не изменён.

Приёмы документации сверены с [Code panel в Storybook](https://storybook.js.org/docs/writing-docs/code-panel), [registry в shadcn/ui](https://ui.shadcn.com/docs/registry/getting-started) и [предложением llms.txt](https://llmstxt.org/). Используются существующие ES-модули проекта, сторонние фреймворки и npm-зависимости не добавлены.

## Запуск

Нужен Node.js 20 или новее. Внешних npm-зависимостей нет, `npm install` не требуется.

```sh
npm run dev
```

Открыть http://localhost:4173/. Команда сначала собирает сайт и запускает локальное превью. Чтобы выбрать другой порт: `PORT=4174 npm run dev`.

```sh
npm run build
npm run check
npm run preview
```

`build` создаёт `dist/`; `check` проверяет полноту переноса, источники, внутренние ссылки, якоря, изображения и индекс поиска. `preview` показывает уже собранный `dist/`. Превью доступно только на этом компьютере и не публикует материалы в интернете. Остановка — Ctrl+C в терминале сервера.

## Обновление статей

1. Получить разрешение пользователя на изменение текста. Дословно перенести согласованную версию PDF в нужный файл `content/articles/`, сохранив авторские формулировки.
2. Сохранить первый заголовок `#`, заголовки разделов `##` и подразделов `###`. Из них строятся оглавление и ссылки на разделы.
3. Для ссылки на другую статью использовать `[текст](/docs/input/)`. Для примера из PDF — `![содержательное описание](01)`, где `01` — идентификатор вырезки в `content/figures.json` для этой статьи. Описание служит только альтернативным текстом изображения; отдельная редакторская подпись не выводится.
4. После визуальной сверки обновить запись статьи в `content/pdf-text-lock.json` (SHA-256 PDF и Markdown), выполнить `npm run build && npm run check`, затем обновить страницу превью.

Встроенный Markdown поддерживает абзацы, заголовки двух уровней, одноуровневые списки, жирный текст, ссылки и иллюстрации. Произвольный HTML не исполняется. Для вложенных списков, таблиц или другого синтаксиса нужно сначала расширить обработчик в `scripts/build.mjs`.

Чтобы добавить статью, создать Markdown-файл, добавить его идентификатор и английское название в `content/catalog.json`, а источник и вырезки — в `content/figures.json`. Проверку ожидаемого числа статей в `scripts/check.mjs` обновить вместе с каталогом. Сейчас она намеренно сверяет все 20 исходных PDF.

## Дизайн и живые примеры

Главная основана на черновике Figma `UPIQ2Lv0NgvegbrBxlRejH`, фрейм `4:2`. Оригинальные SVG шестерёнок и значки сохранены в `public/assets/brand/`; фирменная надпись набрана текстом шрифтом SB Sans Display. Все ресурсы локальные — сайт не запрашивает Figma, CDN или внешние шрифты при открытии. Иконки интерфейса перечислены в `scripts/site-icons.mjs` и копируются из `Icons` без изменения SVG. Проверка сборки сравнивает их с оригиналами, а также проверяет встроенные иконки компонентов и неизменность файлов исполнения `ui-kit`. Кнопка «Проветрить» плавно ускоряет шестерёнки на пять секунд, после чего они возвращаются к обычной скорости без скачка угла. Повторный запуск доступен после завершения цикла. При уходе со страницы цикл завершается; системная настройка уменьшения движения отключает вращение и скрывает кнопку. Фон главной использует новый контур из Figma `95:230` (фрейм `95:156`), сохранённый без изменений в `public/assets/brand/gear-cog.svg`. Матовое стекло, тонкая кромка, толщина и тень создаются CSS-слоями в `public/home-background.css`; этот файл подключается только на главной. Обе шестерёнки привязаны к краям основной колонки, на узких экранах сильнее уходят за границы. Декорация не принимает события мыши и учитывает уменьшение движения.

Адреса кнопок Pixso и Сберчат заданы пользователем в `content/resources.json`. Сберчат использует оригинальную иконку `24 Linear / Comment.svg`. Имена контактов на главной — ссылки mailto; отправка письма сайтом не выполняется.

Живые примеры, настройки (Select Sm), поля поиска и кнопки интерфейса подключают `ui-kit` напрямую, без второй реализации компонентов. Поиск в шапке и меню использует Md, на главной и странице результатов — Lg. Оригинальная лупа подключается параметром `leftIcon` общего Field: размеры и отступы выбираются из `_Markup` в Field.json, включая сочетание с правым крестиком очистки. Подписи источников на страницах не показываются; привязка материалов остаётся в `content/figures.json`. Поиск запускается по Enter только с непустым запросом; пробелы по краям удаляются. Общие стили фокуса витрины не применяются к `.cp-input`, чтобы не добавлять внутреннюю рамку поверх состояния компонента. После изменения библиотеки нужно пересобрать сайт. Обычные поля в примерах имеют исходную ширину 250 px; дата и время используют `width: 'auto'` и подбирают ширину по маске и иконке. Панель настроек остаётся справа от примера, на телефоне переносится вниз. Для кнопки доступны все девять Use из библиотеки и совместимые Type. Сборка копирует только файлы исполнения, используемые SVG и шрифты; исходные JSON компонентов, временные стенды и продуктовые прототипы в `dist/` не попадают. Страница типографики строится из `ui-kit/text-styles.json`. Изменения размеров или состояния в примере действуют только до ухода со страницы и не меняют документацию.

## Устройство проекта

- `content/articles/` — редактируемый текст; содержание отделено от оформления.
- `content/catalog.json` — категории, порядок и поисковые синонимы.
- `content/figures.json` — соответствие статьям и PDF: относительный путь, номер страницы, координаты вырезки от левого верхнего угла в PDF-единицах, размеры для отображения.
- `public/assets/` — иллюстрации WebP. Небольшие изображения не растягиваются шире исходных размеров. Иллюстрации статичные, без полноэкранного раскрытия.
- `public/styles.css`, `public/app.js`, `public/demos.js` — оформление, поиск, навигация и подключение живых примеров.
- `scripts/build.mjs` — чтение Markdown и подготовка содержания; `scripts/render-site.mjs` — шаблоны страниц, статическая сборка и копирование используемых ресурсов библиотеки. Отдельный HTML для каждого адреса и JSON-индекс поиска.
- `scripts/serve.mjs` — только локальный сервер предпросмотра с настоящим ответом 404.
- `docs/EDITORIAL-QUESTIONS.md` — внутренние редакторские вопросы, не включаются в сайт.
- `docs/QA.md` — результаты проверки и ограничения первой версии.

Исходные PDF, отчёт Cool Score, `tmp/`, редакторские вопросы и скрипты не попадают в `dist/`.

## Повторное извлечение иллюстраций

Готовые изображения уже сохранены: для запуска сайта Python не нужен. Для повторного извлечения нужны Python, `pdfplumber` и `pypdfium2`:

```sh
python3 scripts/extract-figures.py
```

Скрипт перезапишет вырезки и их манифест. После изменения исходных PDF нужно визуально проверить координаты: автоматический поиск панелей зависит от оформления PDF. Карточки, скругления, отступы и пошаговая схема токенов имеют ручные координаты. `scripts/inspect-pdfs.py` создаёт вспомогательные тексты и рендеры в `tmp/site-pdfs/`; эти материалы не являются содержанием сайта.

Описания в `content/articles/` переносятся из PDF дословно: без сокращений, пересказа, исправления авторских формулировок и дополнительных рекомендаций. Менять их можно только с разрешения пользователя. Разрешено адаптировать HTML-разметку, переносы строк и адреса внутренних ссылок, сохраняя видимый текст. Иллюстрации статичные; редакторские подписи, которых нет в PDF, не добавляются.

`content/pdf-text-lock.json` фиксирует проверенную транскрипцию и SHA-256 исходных PDF. Сборка отклоняет изменение Markdown без обновления согласованной транскрипции; `npm run check` дополнительно сверяет PDF, видимый текст итоговых статей и отсутствие увеличения картинок. Обновлять контрольные суммы можно только после разрешённого изменения и повторной сверки с PDF, а не автоматически при каждой сборке. Экспорт PDF может содержать невидимые дубли, текст контурами и колонки: такие места проверяются по рендеру страницы.

## Размещение после согласования

Сайт статический: достаточно загрузить **содержимое `dist/`** на утверждённый корпоративный хостинг в корень домена. Сервер приложения, база данных, CMS и авторизация в проекте не нужны. Ограничение доступа при необходимости настраивается на стороне корпоративного хостинга.

Для Nginx: `root /path/to/dist; index index.html;` и `try_files $uri $uri/ =404;` в location, а также `error_page 404 /404.html;`. Не настраивать SPA-подмену всех неизвестных адресов главной страницей. Для другого статического хостинга включить адреса с `index.html` в подкаталогах и пользовательскую `404.html`. При размещении в подкаталоге нужно добавить поддержку базового пути: текущие ссылки начинаются с `/`.

Проверка перед размещением: `npm run build && npm run check`. Обновление содержания публикуется тем же способом. Поиск выполняется в браузере, поэтому индекс `search-index.json` должен быть доступен вместе с HTML и изображениями. Вся опубликованная документация и поисковый индекс доступны посетителю сайта; приватность обеспечивает выбранный хостинг. Не загружать весь рабочий каталог вместо `dist/`.

### GitHub → Vercel

В корне добавлен `vercel.json`: Framework — Other, Build Command — `npm run build`, Output Directory — `dist`. Установка зависимостей пропускается: сборка использует только Node.js. Адреса разделов заканчиваются `/`; неизвестные адреса должны отдавать собственную `404.html`, без SPA-подмены главной.

1. Создать приватный репозиторий GitHub и отправить в него файлы, разрешённые `.gitignore`.
2. В Vercel выбрать Add New → Project, подключить GitHub и импортировать этот репозиторий. Root Directory оставить корнем репозитория; настройки сборки берутся из `vercel.json`.
3. До публикации определить доступ к витрине. Приватный GitHub-репозиторий сам по себе не закрывает сайт: доступ настраивается отдельно в Deployment Protection Vercel.
4. После деплоя проверить главную, `/docs/input/`, `/search/?q=кнопка`, изображения и неизвестный адрес. Последний должен возвращать HTTP 404.

После подключения изменения в основной ветке запускают новый production-деплой. Ветки и pull request используются для предварительного просмотра.

В репозиторий не входят исходные PDF, выгрузки `Компоненты`, материалы исследований, прототипы, внутренние отчёты, временные файлы и готовый `dist/`. Код компонентов, статьи, иллюстрации, SVG и web-шрифты нужны для сборки и входят в репозиторий. `npm run check` пока требует локальную папку исходных PDF для проверки полноты переноса; поэтому на Vercel запускается только сборка. Оригиналы остаются в рабочей папке и не удаляются.
